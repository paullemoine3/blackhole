# Spécifications 0.8.6 — Recall, onglet trou noir, split pilote, liens propres, Wormhole, surlignages

Six fonctionnalités, écrites dans les règles du dépôt : logique pure et testée dans `domain`,
persistance et réseau dans `infrastructure`, rien de bloquant sur le thread UI, aucune télémétrie,
données de page insérées par `textContent`, une page web ne peut envoyer que des `PageEvent` sans
pouvoir. Interface sur les composants existants (palette, menus, Bibliothèque, Réglages) et les
tokens `--bh-*`.

Limites communes : vérifié sous Windows par Clippy, tests unitaires et `scripts\test-features.ps1`
(27 contrôles, 10 captures) ; côté macOS par Clippy en compilation croisée seulement, sans scénario.
Android : aucune de ces fonctions n'est portée (voir Wormhole pour le comportement de repli).

## 1. Liens propres

**But.** Une adresse ne trahit plus d'où vient le clic : paramètres de pistage retirés, pages de
redirection sautées.

- Règles : `domain/clean_link.rs`. `strip_tracking` (liste globale `fbclid`, `gclid`, `utm_*`,
  `pk_*`, `mtm_*`… et paramètres propres à un site : `si` sur YouTube/Spotify, `s`/`t` sur X),
  `unwrap_redirect` (Google `/url`, `l.facebook.com/l.php`, `duckduckgo.com/l/`, `out.reddit.com`,
  `youtube.com/redirect`… seulement vers une adresse http(s)), `clean` (3 sauts au plus).
- Application : `PrivacyPolicy::evaluate` nettoie avant le passage en https ; la cible d'une
  redirection est jugée comme toute adresse (une page de redirection ne contourne pas les listes).
- Interrupteur : bouclier `clean_links` (`Shields`, `settings.json`, activé par défaut),
  Réglages > Privacy > Shields. Coupé, seul le passage en https reste.
- Interface : « Copy clean link » dans le menu des liens ; compteur de la session dans le rapport
  de confidentialité (`Msg::LinkCleaned`).
- Le retrait des paramètres existait déjà (liste plus courte, sans interrupteur) : il est
  étendu, pas ajouté.

## 2. Split pilote

**But.** Dans une vue partagée, les liens cliqués dans un volet s'ouvrent dans l'autre : une
liste (résultats, flux, sommaire) reste en place pendant qu'on lit ses entrées.

- Règles : `domain/pilot.rs` (`target` : le pilote conduit l'autre volet, de quelque côté qu'il
  soit ; `leaves_page` : une ancre de la page ne quitte pas le volet).
- App : `app/src/pilot.rs`, état de session `Running::pilot`. Le shell pose `window.__bhPilot`
  dans la page du pilote (reposé à chaque chargement) ; `page_guard.js` remet alors au shell les
  clics simples (`PageEvent::PilotLink`). Le shell vérifie qui est le pilote et évalue l'adresse
  comme toute navigation ; si l'onglet n'est pas le pilote, le lien se charge dans l'onglet même.
- Interface : bouton flèche sur chaque volet de `splitbar.html` (`aria-pressed`), actions de
  palette « Pilot split… » / « Stop the pilot split ». Le pilotage s'arrête avec le split.
- Coût : aucun script ni vue en plus ; un écouteur de clic qui ne fait rien hors pilotage.

## 3. Onglet trou noir

**But.** Un onglet avec sa propre session (cookies, stockage), détruite à sa fermeture : deux
comptes côte à côte, un site douteux, sans ouvrir de fenêtre privée.

- Domaine : `Workspace::open_burner` / `is_burner` (état de session). Jamais épinglé, rangé dans
  un dossier, réutilisé pour une adresse, proposé au rangement ni synchronisé.
- Service : `BrowserService::open_burner` ; `page_changed` n'écrit rien dans l'historique.
- Persistance : jamais écrit dans `workspace.json` ; absent de l'archive, de Recall et des
  surlignages.
- Vues : `views::Store::Burner(id)`. macOS : magasin WebKit éphémère par vue. Windows : profil
  InPrivate `BlackHole-burn-<lancement>-<id>`, supprimé à la fermeture
  (`macos-webext::delete_profile`) ; les dossiers des lancements précédents sont balayés au
  démarrage (`remove_burner_profiles`).
- Efficience : la page d'un trou noir n'est jamais mise en veille (sa session partirait avec) ;
  en contrepartie quatre au plus (`MAX_BURNERS`).
- Interface : action de palette « New black hole tab » (le champ l'annonce), « Open link in
  black hole tab » dans le menu des liens, marque `hole` sur l'onglet dans la barre latérale.
- Vérifié sous Windows : le trou noir ne voit pas les cookies de l'espace et aucun dossier de
  profil ne reste après sa fermeture. Non vérifié : l'isolation entre deux trous noirs.

## 4. Surlignages et notes

**But.** Marquer un passage d'une page, le retrouver marqué à chaque retour, y joindre une note,
l'envoyer dans un Easel.

- Domaine : `domain/highlights.rs` (`Highlights::add/remove/set_note/for_page`, citation 1000
  caractères, contexte 48 de chaque côté, note 2000, 100 par page, 500 pages).
- Stockage : `highlights.json` (`HighlightStore`, écriture différée `write_later`).
- Page : `ui/highlights.js` retrouve les passages dans le texte (mots de la citation, espaces
  libres, contexte pour départager) et les peint avec l'API CSS Custom Highlight : aucun nœud de
  la page n'est modifié. Contenu tardif : nouvel essai sur mutation pendant 30 s au plus, tant
  qu'un passage manque. Rien ne tourne sur une page sans surlignage.
- Shell : `app/src/highlights.rs`. La sélection est lue à l'ouverture du menu ; la page ne fait
  que répondre, l'adresse vient du moteur, tout est borné par le domaine. L'identifiant d'un
  surlignage sous le pointeur (fourni par la page) est vérifié contre ceux de cette page.
- Interface : « Highlight » dans le menu d'une sélection et dans la palette ; sur un surlignage :
  note, copier, retirer ; Bibliothèque > Highlights (recherche, note en place, ouvrir et faire
  défiler jusqu'au passage, épingler dans l'Easel courant, tout effacer en deux clics).
- Jamais en fenêtre privée ni dans un onglet trou noir. Pas de synchronisation entre appareils.

## 5. Recall

**But.** Retrouver une page lue à partir de quelques mots de son contenu.

- Désactivé par défaut. Réglages > Privacy > Recall, ou la première ouverture de la recherche.
- Jamais retenus : fenêtres privées, onglets trou noir, pages d'erreur, pages avec un champ de
  mot de passe (le script ne renvoie rien), adresses locales ou avec identifiants, sites de la
  liste d'exclusion (`Settings::recall_exclude`).
- Domaine : `domain/recall.rs` (`indexable`, `terms`, `score`, `snippet`, `shard_of`, `upsert`).
  Correspondance sans casse ni accents ; tous les mots doivent être trouvés ; le titre pèse le plus.
- Stockage : `infrastructure/recall.rs`, fil dédié. 64 fichiers `recall/NN.bin` chiffrés
  (ChaCha20-Poly1305, clé du coffre dans le trousseau du système), 32 pages par fichier, 12 000
  caractères par page. Retenir une page réécrit un fichier ; rien ne reste en mémoire plus de
  30 s après une recherche. Sans trousseau : rien n'est retenu.
- Lecture : 4 s après le chargement, une fois, seulement si la page est à l'écran ; pas de
  relecture de la même adresse avant 10 min.
- Interface : palette en mode `recall` (action « Recall… », raccourci `mod+shift+f`), résultats
  avec extrait ; Réglages : interrupteur, nombre de pages, sites exclus, « Forget everything ».
  Effacer l'historique (ou une de ses pages) efface aussi Recall.

## 6. Wormhole

**But.** Envoyer un texte ou un fichier à un appareil appairé, sur le réseau local, sans serveur.

- Transport : le service `handoff` existant (UDP, ChaCha20-Poly1305, clé de la paire). Nouveaux
  messages `beam` (annonce : type, nom, taille, parties, SHA-256), `beam_reply`, `chunk`.
  Une version qui ne les connaît pas ne lit pas le paquet : l'envoi échoue proprement.
- Règles : `domain/wormhole.rs` (texte ≤ 64 Ko, fichier ≤ 64 Mo, parties de 3000 octets,
  `acceptable`, `safe_name` : jamais un chemin, ni un nom réservé de Windows).
- Extrémités : `infrastructure/wormhole.rs`. Fenêtre de 16 parties acquittées ; le fichier reçu
  s'écrit dans `<téléchargements>/<nom>.<id>.part` et n'est renommé qu'entier et conforme au
  SHA-256 annoncé ; un transfert arrêté ne laisse rien.
- Consentement : un texte arrive seul mais n'est copié que sur « Copy » ; un fichier attend
  « Accept » (2 min), n'est jamais ouvert de lui-même. Un transfert à la fois par appareil.
- Interface : « Send to … » dans le menu d'une sélection ; palette : « Send the clipboard's text
  to … », « Send a file to …… » ; le fichier reçu apparaît dans Library > Downloads.
- Android : affiche un texte reçu, refuse aussitôt un fichier, n'envoie rien.
- Non vérifié : un échange réel entre deux machines (test bout à bout en boucle locale seulement),
  pas d'annulation en cours de transfert, pas de barre de progression.
